# Q-410 — Which item tailors case for Turkish, Azerbaijani and Lithuanian?

Asked by the library lane's items of 2026-11-27 on 2026-11-27.

R22.45 compares Unicode text without case through `core/unicode`'s
default full case folding. That
folding is right for every language except Turkish and Azerbaijani,
where dotted and dotless I fold apart, and Lithuanian, which keeps a dot
above in lowercase. Tailoring needs a locale, and a locale is an explicit
value (D1955) that R22.50 brings. R22.50's text formats numbers and text
for a locale and does not say whether it tailors case as well.

**Options:**

1. R22.50 tailors case mapping, folding and caseless comparison for the
   three locales, from CLDR and the Unicode database's special casing, taking the
   locale value it introduces; R22.45's calls stay locale-free.
2. R22.45 takes a Turkic choice as a flag, folding I as the database's Turkic
   entries say, with no locale value, and R22.50 adds nothing for
   case.
3. Neither: tailored case waits in the Broader standard library family
   until a program asks for it.

**Recommendation:** option 1. The tailoring belongs with the locale
value, and a flag in R22.45 would be a second way to name a language
that R22.50 then has to keep.

**Default until answered:** R22.45's calls use the default full folding
and say that they are wrong for Turkish, Azerbaijani and Lithuanian, as
`core/unicode`'s case mappings already say; R22.50 is planned without
case tailoring until the answer adds it.

**What waits on the answer:** R22.50's scope, and one sentence of R22.45's
documentation.

**Answer (2026-11-27, the maintainer):** option 1. R22.50 tailors case
mapping, folding and caseless comparison for Turkish, Azerbaijani and
Lithuanian with the locale value it introduces, and R22.45's calls stay
locale-free.

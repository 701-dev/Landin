# Q-150 — Is a locale an explicit value passed like a capability?

Asked by R20.10 on 2026-11-22.

The inventory's ninth question. Nothing in `core` carries a locale, and
`core/README.md` says no locale is consulted anywhere. SR-98 plans locale
formatting over generated CLDR data, a locale made from a BCP 47
identifier. R20 fixes the shape so R22's additions follow it.

**Options:**

1. An explicit value, made from a BCP 47 identifier, passed to the routines
   that need one; the host's preferred locale is read through
   `hosted/system` like any other host fact. No global locale.
2. A capability concept (`type is locale`) with entries, so a program may
   supply its own provider, as with entropy.
3. A process-wide locale set from the host, as C's `setlocale`.

**Recommendation:** option 1. A locale is data, not an authority, and a
value keeps the result reproducible.

**Default until answered:** the inventory's: an explicit value as SR-98
says, no global locale.

**What waits on the answer:** R22's locale additions; nothing in R20's
items.

# Q-411 — Does a C program on Windows get a way to establish the argument root?

Asked by R22.28 on 2026-11-27.

On Linux, FreeBSD and Darwin a C program whose `main` calls hosted Landin
code establishes the argument root first, through
`_landin_host_initialize_arguments`; `abi/r440-native-renamed-main` holds
that. On Windows `_landin_start` keeps the root itself (D2269) and nothing
C can call establishes it, so that fixture names no Windows target (D2963)
and a C program on Windows that calls hosted Landin code reading its
arguments has no root. Whether Windows gets such an entry is a change to
what D2269 chose and to `hosted/system`'s surface on Windows, so yours.

**Options:**

1. Keep D2269: a C program on Windows calls only Landin code that reads no
   arguments, and the fixture stays off Windows.
2. Add a C-callable initializer for Windows, which reads the command line
   as `_landin_start` does, and give the fixture a Windows arm.

**Recommendation:** option 1 until a Windows program whose C `main` calls
hosted Landin code is met; no one has asked for one.

**Default until answered:** D2269 stands, no initializer on Windows, and
`abi/r440-native-renamed-main` names no Windows target.

**What waits on the answer:** nothing; a Windows arm of the fixture would
follow option 2.

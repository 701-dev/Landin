# Q-171 — Which atom names absence, and which module declares it?

Asked by R20.50 on 2026-11-22.

D1953 gives absence one name. Today it is seven atoms: `map.missing`,
`tree.no_such_node`, `io.not_found`, `text.not_found`, `io.no_argument`,
`io.no_variable` and `posix.no_account` (with `posix.no_symbol` beside
them). An atom is one declaration and an import is never re-exported, so
one name means one module that declares it, low enough in the import
graph that `core/text`, `core/io`, `core/map` and `core/tree` can name it.
`core/mem` imports nothing and already declares the atoms every container
shares (`out_of_bounds`, `empty`, `full`, `out_of_memory`, D269). The
spelling and the module are a choice of name, which is the maintainer's.

**Options:**

1. `mem.not_found`, declared in `core/mem` beside the containers' shared
   atoms: no new module, every module that needs it already imports
   `core/mem` or can at no cost, and `not_found` is the spelling the tour
   teaches at [0630] and that ENOENT's readers expect.
2. `mem.missing`: the same module, the map's spelling.
3. `not_found` in a new bottom module of its own for the library's shared
   failure atoms, with `out_of_bounds`, `empty` and the out-of-room atom
   moved there too, so a missing file is not spelled through `mem`.

**Recommendation:** option 1. It adds no module, follows D269's home for
shared atoms, and keeps the spelling the most programs already handle.

**Default until answered:** `mem.not_found`, declared in `core/mem`, and
the breaking list's absence entries are written with it.

**What waits on the answer:** only the spelling R20.60 writes; R20.50's
list and every other entry are written with the default.

**Answer (2026-11-22, the maintainer):** through the manager's chat, as
recommended, option 1: `mem.not_found`, declared in `core/mem`. R20.60
applied it. Closed.

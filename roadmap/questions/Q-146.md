# Q-146 — Should `platform/posix` sit below the protocol concepts rather than above them?

Asked by R20.10 on 2026-11-22.

The inventory's fourth question. `platform/posix` imports `core/io`,
`core/net`, `core/text` and `core/failure`, so the system layer depends on
the abstractions built over it, while `hosted/events` already bypasses
posix for epoll and kqueue.

**Options:**

1. Move it below as far as its types allow: posix speaks descriptors,
   byte slices and errno, and `hosted/system` adapts it to `core/io` and
   `core/net`.
2. Leave it where it is: posix is the hosted implementation of the
   protocols, and the upward edge is an implementation import.
3. Move it below and route `hosted/events` through it as well, so one
   module owns every system call wrapper.

**Recommendation:** option 1. It removes the upward edge without a rule
for events, whose readiness calls differ per host.

**Default until answered:** the inventory's: below, as far as its types
allow, `hosted/system` adapting to `core/io`.

**What waits on the answer:** R20.40's import graph.

**Answer (2026-11-22, the maintainer):** option 1. Recorded as D1951.

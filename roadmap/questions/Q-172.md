# Q-172 — Which atom names running out of room?

Asked by R20.50 on 2026-11-22.

D1953 gives running out of room one name. Today an allocator that cannot
satisfy a request fails `mem.out_of_memory` (in 119 files), raw storage
with no spare slot `mem.full`, a text builder or `text.encode` whose
buffer is too short `text.no_space` (54 files), and a line reader whose
buffer cannot hold a line `io.line_too_long`. Each is the same answer to
the caller: what was asked does not fit in the memory it was given, and
a program that swaps a growing vector for a fixed buffer should handle
the same atom. The spelling is a choice of name, which is the
maintainer's.

**Options:**

1. `mem.out_of_memory`: the spelling in most failure sets already, so the
   fewest rewrites, and the one a newcomer from C or Rust reads first; a
   fixed buffer that is too short is memory that ran out.
2. `mem.full`: the shortest, and exact for a fixed buffer or a pool; it
   reads less well for a heap that refuses a size.
3. A new spelling, `mem.no_room`, neutral between a heap and a buffer, at
   the cost of rewriting every failure set.

**Recommendation:** option 1.

**Default until answered:** `mem.out_of_memory` is the one atom, and
`mem.full`, `text.no_space` and `io.line_too_long` are rewritten to it.

**What waits on the answer:** only the spelling R20.60 writes.

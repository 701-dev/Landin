# Q-142 — Does the R23 gate hold while Homebrew is checked only by hand after a release?

Asked by R23.50 on 2026-11-21, at the claim of the R23 gate.

The R23 gate asks for every route in the installing documentation to be
exercised by the gate or, where only a release can, by the release
workflow. The README documents six routes. Five are: the install script
(`install_check.py` in `release`, `arm64-release` and
`darwin-host-release`), a release archive (the gate's packaged compiler,
`static_check.py`, and the release workflow's checks before approval), the
container (the user image in `outside-user-stock` and
`arm64-release-checks`, both images in the release workflow), nix
(`nix_route.py` in `flake-compiler`) and the source build. Homebrew is
not. Its formula lives in the maintainer's tap, `JanHaan/homebrew-tap`,
whose only workflow, `bump-landin`, points the formula at a release and
commits without running `brew install` or `brew test`. Step 8 of the
release recipe in `docs/process.md` checks the formula by hand, on a Mac
and on Linux, and calls the tap outside this repository's gate. Whether
that suffices, or the gate asks for more, decides whether the phase is
done. The gate text is the maintainer's, and so is the tap.

**Options:**

1. Claim the gate as it stands: Homebrew is a route only a release can
   exercise, and the recipe's step 8 is its check, though a manual one
   rather than the release workflow.
2. Exercise the formula in the tap: its bump workflow runs `brew install`
   and `brew test` on macOS arm64 and Linux after moving the formula, and
   the recipe's step 8 reads that run. Claim the gate after the next
   release's bump passes.
3. Exercise the formula in this repository's gate: a job installs the
   tap's formula with its URL and sums pointed at the gate's packaged
   archive and runs `brew test`, on macOS arm64 and Linux; a new item in
   R23 before the claim.
4. Narrow the gate to the four routes the phase added and claim it, with
   Homebrew left as the recipe's manual step.

**Recommendation:** option 2. It is cheap, it runs where the formula
lives, and it checks the formula against the archive a release actually
published, which a gate job could only imitate; it needs a change to the
maintainer's tap, which this repository cannot make.

**Default until answered:** the R23 gate stays unclaimed; nothing else
changes.

**What waits on the answer:** the claim of the R23 gate, and with it
nothing in the serial lane, which R19 to R22 hold.

**Answer (2026-11-22, the maintainer):** option 1: the gate is claimed as
it stands. Homebrew is a route only a release can exercise, and step 8 of
the release recipe in `docs/process.md`, checking the tap's formula by
hand on a Mac and on Linux, is its check; the tap keeps its workflow as it
is. Closed.

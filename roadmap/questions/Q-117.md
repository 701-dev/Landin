# Q-117 — Is naming glibc's source package enough, or does a release publish glibc's source too?

Asked by R23.50 on 2026-11-21.

From the release after 0.2.11 each Linux archive holds glibc, linked
statically (D1787), and glibc is under the LGPL, version 2.1 or later.
The archive carries `LICENSE-GLIBC`, the copyright file of the Ubuntu
`libc6-dev` package whose `libc.a` was linked, and `NOTICE-GLIBC`, which
names that package's version and source package, says `apt-get source
glibc=VERSION` fetches it, and says how to relink `refine` with a modified
glibc from Landin's public source (D1788). The LGPL's section 6 asks the
distributor of a work linked with the library to make the library's
source available with it, by accompanying it, by a written offer, or by
offering it from the same place. Pointing at Ubuntu's archive is common
practice, but whether it meets that obligation for this project's
releases is a licensing judgement, and the project's published shape, so
it is the maintainer's.

**Options:**

1. The notice as it is: the archive names the exact Ubuntu source package
   and how to fetch it, and the release publishes nothing more.
2. The release workflow also publishes, beside the Linux archives, the
   glibc source package the runner's `libc6-dev` was built from (about
   20 MB, fetched with `apt-get source` in the build job), and
   `NOTICE-GLIBC` names that asset.
3. A written offer in `NOTICE-GLIBC` to provide glibc's source on request
   for three years, with no asset.

**Recommendation:** option 2. It meets the obligation by offering the
source from the same place as the archive, depends on no third party
keeping an old package version, and costs one step in the release
workflow and one asset per release.

**Default until answered:** the notice as it is, naming Ubuntu's source
package; no glibc source asset is published.

**What waits on the answer:** nothing in R23.50, which completes on the
default; option 2 or 3 is a change to the release workflow and the notice
before the first release that publishes a static archive.

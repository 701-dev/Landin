# Q-118 — Does a release offer the static and the dynamic Linux archive both, and how does the installer choose?

Asked by R23.50 on 2026-11-21.

Q-116 was answered that the static Linux archive replaces the dynamic one
under the same names. After the musl spike reported, the maintainer
reopened that answer: a decision reopened is a new question, and this one
records it. The static archive, glibc linked in (D1787), starts on every
Linux measured; the dynamic one uses the system's glibc and its fixes but
needs glibc 2.38 or later and its loader, so it does not start on Debian
12, Ubuntu 22.04, RHEL 9, NixOS or a musl distribution. Which archives a
release publishes, under which names, and which one the installer takes
by default is the project's published shape, so it is the maintainer's.

**Options:**

1. Static only, under the platform's names, as Q-116 answered.
2. Both: the static archive under the platform's names and the dynamic
   one beside it as `landin-VERSION-PLATFORM-dynamic.tar.gz`;
   `install.sh --variant static|dynamic` chooses, static by default.
3. Both, as in 2, with dynamic the installer's default.

**Recommendation:** option 2. Every consumer that takes the platform's
name, Homebrew, the flake's `refine-bin` and the user image, keeps taking
an archive that starts everywhere, and a user who wants the system's
glibc names it.

**Default until answered:** option 2's names, with static the installer's
default.

**What waits on the answer:** nothing; R23.50 carries option 2 out. Only
the installer's default, static, was not stated by the maintainer and is
taken by default.

**Answer (2026-11-21, the maintainer):** both variants per architecture,
the static and the dynamic archive, reversing Q-116's answer; the
installer chooses between them by a parameter, whose form was left to the
item. R23.50 publishes the static archive under the platform's names and
the dynamic one as `landin-VERSION-PLATFORM-dynamic.tar.gz`, and
`install.sh --variant static|dynamic` chooses, static by default. Closed.

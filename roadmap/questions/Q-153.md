# Q-153 — Does `zeroable` stay a bound a program can write (SC-18)?

Asked by R20.10 on 2026-11-22.

R19 left SC-18 here, to be decided with SC-17 once the library's generic
containers were known. `zeroable` [0550] is the one compiler-owned
concept; [1350]'s `cleared` uses it. The library has no use since
`core/spill` replaced `core/small` without it, and about nine fixtures
and prototype 3 write it.

**Options:**

1. Remove it as a written bound: the compiler keeps knowing which types
   have a zero image ([0540]), [0550] leaves the tour, `cleared` is
   rewritten, and a written `is zeroable` is refused with its
   replacement.
2. Keep it, as the bound a container that needs a filler value states.

**Recommendation:** option 1, unless R20.30 finds a container that needs
a filler; none in the library does today.

**Default until answered:** `zeroable` stays as it is.

**What waits on the answer:** R20.30's entry and the breaking list.

**Answer (2026-11-22, the maintainer):** option 2. `zeroable` stays as [0550] says. Recorded as D1958.

# Q-204 — May SR-1650, slot placement that weighs pressure, be retired?

Asked by R16.30 on 2026-11-23.

SR-1650 asked x86-64's slot placement to weigh the pressure of the values
inside an interval, so that SHA-256's round would hold its eight words and its
bound in registers. R16.30 took what that pressure cost by other means: the
bound is an immediate (D2148), a value with no register is read where its one
use lies (D2156), and a stored value is made in its slot's register (D2157).
The round fell from 58 to 48 instructions. Its word `h` still lives in the
frame, and the stream measured that a register for it would remove two memory
accesses a round and no instruction, so the placement the row asks for no
longer has a measured gain. What SHA-256 still costs against gcc is in its
message schedule's and load loop's checks, now SR-1680. Retiring a row as not
worth doing is the maintainer's.

**Options:**

1. Retire SR-1650: the cost it named is taken, and a pressure-weighing
   placement would be filed again by the first loop measured to lose
   instructions to it.
2. Keep it open, with R16.30's figures, for the next item that changes
   x86-64's slot placement.

**Recommendation:** retire it.

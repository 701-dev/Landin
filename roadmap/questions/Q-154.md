# Q-154 — Does the `caller` parameter stay, and does the library use it?

Asked by R20.10 on 2026-11-22.

R19 kept [1040] with a doubt and sent it here: the compiler fills a
`caller` parameter with the call's file, line and column, so assertions
and logging need no macros. The library, the examples and the prototypes
use it nowhere; about twenty fixtures do. Nothing else does its job.

**Options:**

1. Keep it and give it a library consumer, an assertion or logging
   routine in `core` that takes the call site.
2. Keep it as a language feature without a library use.
3. Remove it, refused with no replacement.

**Recommendation:** option 1. The construct is the only way to say where
a check failed without macros, and a library use makes it something a
newcomer meets.

**Default until answered:** keep it as it is, with no library use.

**What waits on the answer:** R20.30's entry; option 1 adds a routine to
an R20 item.

**Answer (2026-11-22, the maintainer):** option 1. Recorded as D1959.

# Q-363 — How often does the complete gate run once an item's landing on main no longer needs it?

Asked by the gate-time study of 2026-11-26 on 2026-11-26.

The maintainer answered on 2026-11-26 that an item landing on main is no
longer tied to a complete gate: "either we run the complete suite on the
Rx majors, or one a day". R22.37 applies that once R22.36 has measured
the selection, so the complete gate, every lane and the boards with no
reuse, needs a rhythm of its own. The rhythm sets how many landings a
failure found there can stem from: at the study's pace, four or five
landings of code a day, and a phase holds weeks of them.

**Options:**

1. Once a day on main when main moved since the last complete pass, and
   before every phase-gate claim and every release.
2. At each phase's gate only, and before every release.

**Recommendation:** option 1. A defect the selected gate let through is
then found within a day, and the lanes that failed are run on a day's
landings to name the commit; at a phase's gate the same search spans
the phase, and every landing after the defect stands on it.

**Default until answered:** once a day on main when main moved since the
last complete pass, and before every phase-gate claim and every release.

**What waits on the answer:** R22.37's schedule; nothing before R22.37.

**Answer (2026-11-26, the maintainer):** "At all phase gates or once a
day if there was no phase gate": the complete gate, with the boards,
runs at every phase's gate claim, and on main once a day when no phase
gate ran that day and main moved since the last complete pass. A release
runs none of its own; R22.38 plans each onto such a tree, as the
maintainer asked the same day. R22.37 records the rule. Closed.

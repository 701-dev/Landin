# Q-173 — What is a host string called once `host` means only the provider?

Asked by R20.50 on 2026-11-22.

D1953 gives `host` one meaning. It names the I/O provider's handle (the
`host:` parameter every routine takes, `system.host`, `blocking.host`,
`events.host`) and the system the program runs on (`hosted/`), which are
one idea, and also the system's own form of a path or an argument:
`text.host_string`, `host_over`, `host_bytes`, `host_equal`, `from_host`
and the builder's `append_host`. The provider keeps `host`; the string
family needs a name of its own, and that spelling is the maintainer's.

**Options:**

1. `os_string`: `text.os_string`, `os_string_over`, `os_string_bytes`,
   `os_string_equal`, `from_os_string`, `append_os_string`. Rust's
   `OsString` is the nearest precedent a newcomer knows.
2. `system_string`, the same family with `system_`: no abbreviation, but
   `system` is also `hosted/system`'s name and its provider.
3. `native_string`: says what it is without naming an OS, which a
   firmware reader would not have.

**Recommendation:** option 1.

**Default until answered:** the `os_string` family as option 1 spells it,
and R20.40's moved `text.host_variable` becomes `text.os_variable`.

**What waits on the answer:** only the spelling R20.60 writes.

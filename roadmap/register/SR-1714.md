`refine compile p.s --target=cortex-m0 --level=armv7e-m --firmware-layout=ram -o p.elf`, linking the assembly `--keep-asm` kept for an STM32H753 timing image, ends in an internal compiler defect, a failed precondition at `landin-targets-firmware.ads:488` (`Placed_Region`), where the help says "a .s operand is linked as a compiled program is". The same command with the description's `--root` options is refused with L0002, "an assembly operand is linked alone", and with `--firmware-entry` with another L0002, so a kept firmware assembly cannot be relinked by `refine`; `arm-eabi-as` and `arm-eabi-ld --gc-sections --emit-relocs -T OUT.ld` reproduce the image, and those flags are named nowhere. Met making placement variants of the H753's timing images for the H753 slowdown investigation (`~/roadmap3/h753-slowdowns.md`).

Completion: A firmware assembly operand either links with the layout and description it was compiled for, or is refused with a diagnostic that says how to link it; never an internal defect.
Kept: aged past ten by R16.37, which changed IR simplification alone and neither how the driver links an assembly operand nor a firmware layout.

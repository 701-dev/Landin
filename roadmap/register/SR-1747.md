No debugger session steps through a stack switch on Windows. Every other target with a native backend runs D469's session, which holds the leaving and resumed fibres' frames at every instruction of `landin.stack_switch`; on Windows a debugger unwinds by the image's unwind tables, and the switch and start routines, which are hand-written, have none, so the frames below them are not claimed. The Windows debugger lane runs the source and refine dap sessions only (R21.30).

Completion: the switch and start routines carry unwind tables a Windows debugger walks, and `compiler/tests/windows/debug.py` runs switch_frames.py's session.

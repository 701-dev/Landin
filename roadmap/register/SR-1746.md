A Windows program's CodeView describes no inlined copy (D2290). DWARF describes each of D339's copies as an inlined subroutine with its own locals and its call site; on Windows a copy's lines belong to the routine it was copied into, so a debugger stops at its source lines but shows no frame for it, and its parameters and locals are not shown. CodeView's form for it is an `S_INLINESITE` with the inlinee's `LF_FUNC_ID`, whose lines the assembler's `.cv_inline_site_id` and `.cv_inline_linetable` write, which the x86-64 backend's line directives would need to name by copy.

Completion: a Windows image at speed shows an inlined copy as a frame with its locals in LLDB, and a Windows session holds one.

Kept: R22.24 changed process and measurement tools and nothing of Windows debugging; the row waits for a Windows session that stops in a copy.

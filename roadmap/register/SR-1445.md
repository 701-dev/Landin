A breaking window keeps its serial items on one integration branch (Mechanics, "Lanes"), but neither `scripts/item.py`, the landin-change skill nor `docs/process.md` names that branch or how an item lands on it: `start` branches from `origin/main`, and `promote` and `finish` know only main. Met starting R19.10, the window's first item, whose brief had to name `r19-integration` by hand. `item.py start --adopt WORKTREE` takes its base from `merge-base HEAD origin/main`, which for a window branch makes the window's completed dependencies read as unmet unless `--base` names the integration branch (met starting R20.x on `r20-integration`); and `finish` refuses a window item that never promoted unless `--unpromoted`.

Kept: met again by R19.40, whose brief named `r19-integration` by hand and whose `finish` item.py refuses for a window item; the window's items still land on it by hand.

Completion: `item.py` and the skill name a window's integration branch, start its items from it, and land on it in place of main until the phase's gate; `start --adopt` and `finish` take a window item's integration branch, `finish` accepting a head that is an ancestor of it.

Kept: met again by R20.40, which pushed to `r20-integration` by hand and followed its gate with `gate_watch.py` and the full hash, as R20.10 and R20.11 did.

A gate watch ends at the first malformed answer from GitHub's API, though the run it follows goes on. Twice in R21.61, on 2026-11-25, `gate_watch.py --all` stopped with "GitHub did not answer: gh api repos/{owner}/{repo}/actions/runs/RUN/jobs?filter=all&per_page=30&page=1 unexpected end of JSON input" and exit 3, a few minutes into push run 45531070303 and boards run 45539079382, so `item.py`'s recorded watch reads as finished, and the run's state had to be read with `gh run view` and a second watch started by hand. A third, on 2026-11-25, ended a watch of push run 45601164804 the same way with "GitHub did not answer: the job listing of run 45601164804 ended at 69 of its 71 jobs": a listing that came back short rather than malformed.

Completion: `gate_watch.py` asks again, a bounded number of times with a pause, when `gh` answers a jobs page with no JSON or a transient HTTP status, and ends with exit 3 only when GitHub keeps failing, naming the attempts.

Kept: R22.60, the item that took it past ten, changed `core/regex` and `core/unicode` and none of `scripts/gate_watch.py`; the shared poller that landed beside it changed how watches ask, and the row waits for a watch that meets a short or malformed answer through it.

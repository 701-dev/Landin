A NaN's bits at run time are each target's own, which neither `tour.md` nor `spec.md` says, and `spec.md`'s `float.ieee` guarantee says arithmetic NaNs use the canonical quiet pattern. R22.10 met it comparing `core/math`'s results between targets: `inf - inf` is `0xfff8000000000000` on x86-64 and `0x7ff8000000000000` on arm64 and RV64, and `x + 1.0` keeps an input NaN's payload on x86-64 and arm64 and canonicalises it on RV64. D175 says only that the compile-time fold gives the canonical NaN and that payload propagation is no source-visible identity, though a view through an address shows it. R22.11 met it too: `core/complex`'s `tanh` took the sign of an imaginary zero from `sin(2y)`, which for a `2y` that overflowed is the sine of an infinity, a NaN whose sign bit was set on x86-64 and clear on the Cortex-M7 lane, so the result differed by target; it takes the sign from `sin y · cos y` now.

Completion: `spec.md` says which NaN bits a run-time operation gives, either each target's own, stated beside [0240] with the guarantee reworded, or the canonical pattern, with the lowering that makes it so.

Kept: R16.42 added an x86-64 register decision to `spec.md` and changed no float rule or float lowering.

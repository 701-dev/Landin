`scripts/agent_env.sh`'s cached file can hold the caller's whole login environment: on the maintainer's host five of 24 files under `~/.cache/landin/agent-env/`, all written on 2026-11-21 and the current flake's among them, have 98 exports against 73 or 74, a daemon's password included. The SessionStart hook copies the file into every command's `bash -c` argument, so `pgrep -af` and `ps` print the secret and a transcript that shows a process list keeps it. Met reading a process list in the register sweep of 2026-11-22. The cause is not found: a fresh `print-dev-env` sourced under `env -i`, as the script does, adds none of these names (checked that day), so the files came from a run whose shell or `bash` did more than the script assumes.

Completion: the cause found and the script made to write only what the flake's shell defines, with `changed_exports` refusing names that look secret (`PASSWORD`, `TOKEN`, `SECRET`, `CREDENTIAL`), `test_agent_env.py` pinning both, and the recipe saying nothing secret belongs in the exports.

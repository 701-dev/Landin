A binding inferred from an `if` expression takes its first branch's type, so `first := if part == upper then 0 else j end if` with `j` a `usize` is refused with L0301, "this is `usize` and `i32` belongs here", and `part := if c then dense.upper else dense.lower end if` with "not an atom admitted by the set required here", at the second branch; neither note says to write the binding's type, `first: usize = ...` or `part: dense.triangle = ...`, the fix each needs. A literal range, `for i in 0..<6`, is `i32` likewise and cannot index, and its refusal names D18 rather than `0..<usize(6)`. Met in R22.15 writing `core/dense` and by all three of its test translations; L0340 already says, for a generic call's argument, that a literal is `i32` when nothing else decides it.

Completion: each of these refusals' notes shows the written type or the converted bound that fixes it, or `refine fix` writes it.

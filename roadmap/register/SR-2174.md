Passing a generic routine's type parameter as an argument, `resolve(provider, host, name, port, found)` inside a routine whose own `provider: type is network` is in scope, is refused with L0327, "this generic call gives 5 arguments and the template takes 4 arguments", and the note "D138: deduction first matches every runtime argument position". The template's signature, which the refusal shows, has five parameters, so the count reads as wrong, and nothing says that a type parameter is deduced from the arguments and never passed. Met in `core/net`, writing `connect_by_name` and the name-server client, which called their helpers with the type first, as their own signatures list it.

Completion: a call that gives one argument more than the template's runtime parameters, the first a type, is refused saying that the type is deduced and is not passed, with the call written without it, and a negative fixture.

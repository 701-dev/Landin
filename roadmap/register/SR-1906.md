`python3 scripts/register_next.py --decision` answers from the checkout it runs in, so on a branch that does not yet hold main's reservations it hands out a number main has already given away, and says nothing. Met preparing the nix-packages stage-2 candidate on stage 1's unpromoted branch: it answered D2552, inside the range D2551-D2570 that R22.10 reserves on main, the same collision stage 1's own D2551 had met; the fix was to run it again in a fresh `origin/main` worktree, which answered D2571 and up. A branch cut before a reservation landed gets the same wrong answer. The script could fetch and read `origin/main`'s reservations as well as the checkout's, or refuse when the checkout is behind `origin/main`.

Completion: `register_next.py --decision` gives no number that `origin/main` already reserves, or refuses and says to run it on a current main.

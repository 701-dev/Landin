A Windows stack switch leaves the thread's TEB stack bounds, GS:8 and GS:16, naming the stack the process started on. R21.10 had the default report set them to its own stack before the trap (D2192), since Windows dispatches an exception only within those bounds; a prepared stack's code is outside them for as long as it runs, so an exception raised there, a guard page a kernel32 routine probes or a selected handler's fault, is dispatched as an invalid stack. The corpus's fibre fixtures call nothing of Windows on a prepared stack.

Completion: `landin.stack_switch` on Windows saves and restores the TEB's base and limit with the stack it switches, and a Windows fixture calls kernel32 and traps on a prepared stack.

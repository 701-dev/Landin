A `refine` copied out of its build directory looks for its library at `../lib/landin` beside itself, so a snapshot copy kept to measure a base refuses every program importing `core/*`. Two of R16.29's streams met it: `measure.py count --fixture` reported L0518 and suggested `--library`, which `count` does not take, and the Xtensa corpus reported each fixture as a mismatched refusal rather than a missing library, so its first runs were invalid. Each stream built the base in a scratch worktree instead.

Completion: A lane or measurement tool that runs a given `refine` either finds or is told its library (`--library` passed through, or a refusal naming the missing library and the option that supplies it), and no refusal suggests an option the tool does not take.

Kept: R16.34 changed neither how `refine` finds its library nor `measure.py count` nor the Cortex-M corpus's `--program`; it met the copied compiler's library lookup again and laid the library beside the copy.

On a loaded host the Paseo MCP tool that sends an agent a message hangs for 300 seconds and then fails, while `paseo send --no-wait` from a shell, run from `/tmp`, delivers at once. `docs/process.md`'s Paseo coordination points to the `paseo-hubbish` skill and its tools and says nothing of the CLI, so an agent that follows it loses five minutes a message and then the message. Met on 2026-11-27, when twenty agents ran on one host and its memory ran out, and recorded with the tool changes that followed. A related host-local finding, fixed there by a drop-in rather than here: a service with systemd's default `OOMPolicy=stop` loses every agent under it when the kernel kills one compiler.

Completion: the coordination section names the delivery that works under load, or Paseo's tool no longer hangs, or the reason recorded.

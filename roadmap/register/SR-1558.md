`refine fix` applies every exact fix a check offers, warnings' included, and nothing selects which. Migrating the corpus off `complete` (R19.50), `refine fix` on `positive/r491-contextual-statements` also removed the twelve unused locals that fixture keeps on purpose (L0349), and the lines had to be put back by hand; a person migrating their own code off a removed form meets the same thing whenever the program has a warning with a fix. `--help` and D1847 say every exact fix is applied, so nothing was misleading, but there is no `--code=` to apply only the removal's rewrite. R19.60 met it migrating the corpus off five more forms: `--allow all` keeps warnings' fixes out, which nothing in `--help` suggests, but an error's exact fix still goes in, so a negative fixture's own refusal would have been mended with the removal's, and those fixtures were migrated by a script applying only L0696's fixes from the JSON report.

Completion: `refine fix` can be limited to the fixes of named codes, and `docs/commands.md` or its help says how; or the maintainer decides it applies everything and the register says why.

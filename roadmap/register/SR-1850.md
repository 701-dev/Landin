The macOS release archive's `refine` needs macOS 26 and nothing says so. Installing 0.2.11 with `brew install 701-dev/tap/landin` on a GitHub `macos-15` runner succeeded, and its first `refine version` stopped in dyld: `Symbol not found: _posix_spawn_file_actions_addfchdir ... (built for macOS 26.0 which is newer than running OS)`. The release builds on `macos-26` and sets no deployment target, so the minimum is whatever that SDK picks. The README, `docs/capabilities.md` and the formula say only "a Mac with Apple Silicon", and the formula declares no `depends_on macos:`, so Homebrew installs it on a Mac that cannot run it. Met checking the formula's move to 701-dev/homebrew-tap; Linux x86-64 and arm64 installed and passed `brew test` on the same run.

Completion: A stated macOS minimum. Either `refine` is built for an older macOS than the runner's, using a fallback where `posix_spawn_file_actions_addfchdir` is missing, or the README, `docs/capabilities.md` and the formula's `depends_on macos:` name macOS 26. The release workflow checks the archive's `minos` against that minimum. Or the reason it stays unstated is recorded.

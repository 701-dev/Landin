A `refine` built in one checkout and run from another worktree with `refine check --root=. FILE` reads `core/`, `hosted/` and `platform/` from the checkout it was built in, not from the worktree whose `--root` it was given; only an L0016 warning on each import says so, and `--library=.` is what takes the worktree's. An agent working on R22.43's Windows providers in a second worktree, given a brief whose commands said `--root=.`, checked its library changes against the other checkout's sources until it read the warnings. Nothing in `docs/process.md`'s local feedback recipe names `--library`.

Completion: the commands the process and the briefs give for checking a program in a worktree take that worktree's library, by `--library=.` or by `refine` preferring a library under `--root`, and the case is in the local feedback recipe.

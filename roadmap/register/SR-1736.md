`refine compile --target=windows-x86-64 FILE --emit=exe -o out` with no `.exe` fails with L0501, "x86_64-w64-mingw32-clang reported success but produced no executable at out", because the MinGW driver wrote `out.exe` beside the staged name refine asked for; refine then reports L0005, its private files' cleanup failing on a directory not empty, and leaves a `.refine-publication-*` directory in the output's directory. R21.20's threads stream met it compiling a fixture by hand. The refusal does not say to add `.exe`, and the cleanup should not fail at all.

Completion: a Windows executable named without `.exe` is written under the name asked for, or refused up front with the fix named, and a failed link leaves no private directory behind.

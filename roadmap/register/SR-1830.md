`environments/cortex-m/tools.lock.json` fetches 117 Debian packages from `deb.debian.org/debian/pool`, which keeps only each package's current version. On 2026-11-25 `libssl3t64_3.5.7-1~deb13u2_amd64.deb` had been superseded by 3.5.9-1~deb13u1: some of Debian's mirror edges answered 404 for it and others still served it, so R16.38's gate run 45537871389 failed `xtensa-esp32-2` at `setup.py` and passed when the job was run again. The Xtensa jobs keep no cache of the tools, so once every edge drops the file each lane that installs them fails on every branch, main included.

Completion: each locked Debian package fetched from a URL that does not change, `snapshot.debian.org`'s archive of the same file and digest, or `setup.py` falling back to it when the pool answers 404.

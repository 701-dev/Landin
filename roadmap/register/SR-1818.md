`scripts/build.sh` in release mode does not fit 8 GiB at its default parallelism on a 20-processor host, and does not say so. In a Linux arm64 container with 8 GiB and 20 processors the kernel killed `gnat1` on `landin-backend-x86_64.adb` and `landin-backend-arm64.adb` ("Killed signal terminated program gnat1"), and the build failed with no word about memory and no suggestion of `-j`; `-j4`, which the gate's `arm64-release-build` passes without saying why, built it in 4 min 21 s. The debug build fits at 20 jobs. Met running the release half of the test program in that container on 2026-11-24. `environments/freebsd/gnat/build.sh` bounds GCC's own build by memory for the same reason.

Completion: the release build bounds its jobs by the host's memory as well as its processors, or a gnat1 killed by the kernel is reported as memory with the `-j` that fits, and the command reference says it.

Kept: R21.60 added two rows to `docs/process.md`'s gate table and changed neither `scripts/build.sh`'s job count nor the command reference's build section; `environments/freebsd/gnat/build.sh` bounds GCC's jobs by memory.

Six `deb` entries of `environments/cortex-m/tools.lock.json` keep the version's epoch, URL-quoted, in `file`, such as `libbpf1_1%3a1.5.0-3_amd64.deb`, while the pool's and snapshot.debian.org's name for the same file is `libbpf1_1.5.0-3_amd64.deb`. Met on 2026-11-25 writing `environments/cortex-m/lock_snapshot.py` for SR-1830's fix, whose lookup by the lock's `file` found no version and had to take the name from the URL instead. `file` is only where `setup.py` stores the download, so the lanes are unaffected, but a reader matching the lock against Debian's names cannot use it.

Completion: each `file` is the pool's own name, changed with the next lock change, since it changes the lock's digest and every installation record.

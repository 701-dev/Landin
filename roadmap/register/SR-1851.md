A Windows image cannot call a C function whose link name begins with `.L`. The ABI fixture `r440-native-link-namespace` binds `link(symbol: ".L1_1")` to prove a foreign name cannot capture a native routine's; on Linux and FreeBSD its assembly's `call .L1_1` reaches the C definition, but Clang's COFF assembler takes `.L` as its own private prefix and refuses the reference, "assembler label '.L1_1' can not be undefined", on both Windows architectures. R21.70 met it adding the ABI fixtures to the Windows lane (SR-1694) and left this fixture off the Windows targets.

Completion: a COFF image binds and calls a C symbol named `.L…`, by a spelling the assembler takes as an external name, and `r440-native-link-namespace` names both Windows targets.

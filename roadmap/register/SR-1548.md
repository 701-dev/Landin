`check.py` counts a row's age as the items complete in the working `ROADMAP.md` that were not complete in the commit that filed it. When R19's integration branch took main, four rows filed on main that day (SR-1433, SR-1466, SR-1467, SR-1468) were counted against R19.10, R19.30 and R19.40, items completed on the branch before those rows existed, so the close was refused until each was kept with a `Kept:` line. Met closing R19.40; every window item that takes main meets it again.

The other half of the same reading: a `Kept:` line written while resolving a merge does not restart a row's count, because the age reads the line's commits with `git log -G`, which shows no merge's diff. R20.20 met it merging R20.50 into its candidate: SR-1432's new `Kept:` line, in the merge commit, still counted eleven items, and passed only once the same edit was made in a commit of its own.

Completion: A row's age counts only the items completed after it was filed, on the line it was filed on or since the merge that brought it, and a window item taking main is refused for no row the merge alone aged; a `Kept:` line a merge brings or writes restarts the count as one in an ordinary commit does.

Kept: no item has changed `check.py`'s register ages since it was filed, and R20.20 added the merge case above; R20's window has not yet taken main.

A Windows image built above the baseline level does not check the processor at start. A static Linux program's `_landin_start` holds the processor to the executable's level and ends with status 127 and one line on standard error when a feature is missing; Windows' entry runs `main` directly, so on an older processor a `--level=x86-64-v3` build ends with `STATUS_ILLEGAL_INSTRUCTION` at the first such instruction, as a failed check does, with no word saying why. D2189 records that the image carries no level mark and its assembler refuses nothing above the level.

Completion: `platform/windows`'s entry checks the level's features by CPUID before `main`, as Linux's does, and says which is missing.

Kept: R21.20 changed the entry to read the command line and the environment (D2269) and left the processor's level as it was.

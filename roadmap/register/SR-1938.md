An immutable module array is emitted in a writable `.data` section on Linux x86-64, arm64 and RV64, where the firmware backends, Cortex-M, RV32 and Xtensa, put it in `.rodata`; only a text literal is read-only on every backend. R22.30 met it laying out `core/unicode`'s tables: a hosted image carries them in `.data`, so a write through an unchecked pointer changes them silently where D161 makes a text literal's write fault, and [1460]'s "immutable values can stay in flash" holds on firmware alone. A firmware image keeps them in flash, so no RAM is spent on any target.

Completion: every backend emits an immutable module value without relocations in its target's read-only section, `.rodata`, Mach-O's `__TEXT,__const` or PE's `.rdata`, with a fixture whose write through an unchecked pointer faults on each hosted target.

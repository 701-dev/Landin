Generic code over `math.floating` has no way to name its width's facts: the largest finite value, the epsilon, the precision, the exponent range, or a constant such as π rounded to the width. R22.11's `core/complex` branches on `sizeof item == 8` and converts a literal written for each width, since an `f64` literal an `f32` cannot hold is refused in the `f32` instance (L0300) and an `f64` value converted to such an `f32` traps (`bad_conversion`); `core/math` reads the same facts from each width's own routine.

Completion: generic code reaches each width's facts through the concept or its type parameter, and `core/complex` uses them in place of its `pick` helper.

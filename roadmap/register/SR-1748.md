Two `--debug=full` builds of one Windows program differ. LLD names each object in the PDB by its path, and the object is the toolchain driver's temporary file, `/tmp/NAME-XXXXXX.o`, whose name is random; the PDB's GUID, which the image carries, is a hash of the PDB, so the image differs too. A build without debug information is unaffected. LLD makes a relative object path absolute against `/pdbsourcepath:`, so assembling to a fixed relative name in the staging directory and linking from there would make both the same; the tool runner starts no tool in another directory yet. Darwin's debug map names its staged object the same way (docs/targets.md).

Completion: two `--debug=full` Windows builds of one program into one directory give identical images and PDBs, and a check holds them so.

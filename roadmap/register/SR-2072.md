`docs/process.md`'s local feedback recipe says a run started with `run_logged.py --detach --limit SECONDS` outlives a reopened session, and on 2026-11-27 it did not: when the agent host closed every agent session at about 08:20Z, R22.35's two detached runs, its records' exhaustive `f32` check and bit-for-bit digests, two hours in, ended with `interrupted_by: 15`. The detached process leaves its session and process group but stays in the agent's control group, which the host stops whole. The same commands under `systemd-run --user --scope` survived the host closing every session again at 09:58Z. Met restarting them in R22.35; the exhaustive run's `--record` resumed it, the digests had to start their routine again.

Completion: `--detach` puts the run where ending the agent's sessions does not stop it, such as its own systemd user scope where there is one, and says so, or the recipe says what survives what and names the way to start a run that must outlive the agent.

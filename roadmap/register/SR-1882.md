`compiler/tests/test_tool_cancellation.py`'s held-run cases send SIGTERM or SIGHUP to `refine run` after a fixed `min(0.2, whole / 4)` seconds and require the cancellation message; when the runner is loaded the signal can arrive before `refine` has installed its handlers, so the default action ends it, exit -15 with nothing on standard error, and the gate fails. Met in R22.26's gate run 45657590635, `arm64-release-checks`, `held-run-SIGTERM`, on a tree whose three earlier runs passed it and which changed nothing of the driver's signals. The unheld `refine check` case races the same way: R22.30's run 45810784843, `arm64-release-checks`, `unheld-check-SIGINT`, exit -2 0.3 ms after the signal, sent a quarter into a 0.25-second check.

Completion: the test sends its signal only once `refine run` says it holds its directory, or the handlers are installed before anything a loaded host can delay, and a control shows the case passing under load.

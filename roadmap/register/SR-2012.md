Two refusals give contradictory advice for one line. `text.append_u64(line, digits) else return` is refused with L0102, whose help says to write `else begin return end`; the same call written that way as the only statement of an `if` arm, `if negative then text.append_byte(line, u8('-')) else begin return end end if`, is then refused with L0329, "the `else` after it divides the `if` around it", whose note offers `(call(...) else value)` or `else (problem) ... end`, which leaves only the second for a recovery that returns. Met writing `compiler/tests/float-text/exhaustive.ldn`; the program was written with `else (problem) _ = problem return end` instead. R22.45 met it as L0110 in a binding: `found := text.find_last_byte(source, value) else begin return end` as an `if` arm's first statement is refused, "this `else` recovers the call, and written bare it ends the `if` arm it stands in", though the `begin ... end` is the form L0102 asks for; `runtime/core-text-search-everyday` was written with one helper per search instead of one with an `if`.

Completion: L0102's help gives the spelling that holds in every position, or says where `else begin return end` does not; or L0329 recognises the `begin ... end` recovery the other refusal asked for.

Gate run 45953203349, attempt 1 (R22.34's candidate, 2026-11-27): job `freebsd-host-2` (job 140354628039) failed on one outcome, `runtime/network-receive-timeout [size-auto]`, which exited 1 where 42 was expected. That was in the FreeBSD amd64 guest, building and running the test program natively. The job passed when it was rerun as attempt 2, and no outside signature names a cause. The change touched no compiler, library or runtime code. The fixture asks that a receive and an accept limited to 50 ms by `net.set_timeouts` report `net.timed_out` after at least 50 ms by the monotonic clock. FreeBSD rounds `SO_RCVTIMEO` to the kernel's ticks, and a guest's clocks can disagree with each other, so a timeout that ends a fraction early would fail it now and then. The exit status alone does not say which of its checks failed.

Completion: the fixture says which check failed, and either the 50 ms bound is one FreeBSD keeps, stated with the rounding it allows, or the defect it shows is fixed.

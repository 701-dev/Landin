Two refusals met rewriting the corpus to R20's merged atoms said nothing useful. A failure set that names one atom twice, `! mem.not_found | mem.not_found`, is accepted without a word, so every set a merge doubled had to be found by searching. And a qualified name whose module the file does not import, `mem.out_of_memory` in a file without `import core/mem`, is refused as "`out_of_memory` is not declared in any scope" (L0201), or in a type argument "this type argument names no type" (L0304); neither says that `mem` is a library module the file could import. Met applying the breaking list in R20.60, whose own fixes add the import and drop the duplicate only for the names the list removed.

Completion: a warning with an exact fix for an atom named twice in one set, and L0201 and L0304 naming the library module, with its import as a fix, when the unresolved prefix is a library module's name, each pinned by a fixture, or the reason recorded.

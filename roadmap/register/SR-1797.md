The Windows lane's error mode does not keep Windows Error Reporting away, though `check.py` and its README say it keeps "WER's dialog and its wait" away. On a Windows 11 LTSC machine, running the lanes over SSH from a Linux checkout at main af4b2b992, 14 of 3,682 `windows-runtime` outcomes and 32 of 3,682 `windows-microsoft` outcomes did not finish within 60 seconds, every one a `traps: yes` fixture: each trap left a `WerFault.exe` in session 0 using 5 to 20 CPU seconds, and with many at once some outcomes passed the limit. With WER disabled both corpora passed every outcome. The gate passes because GitHub's images disable WER.

Completion: the lane keeps WER away for its own run, the per-user `Windows Error Reporting` `Disabled` value for instance, or the README names the requirement and the lane refuses a host where WER is on.

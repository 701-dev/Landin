The FreeBSD arm64 lane cannot use an arm64 host's KVM without routing around it. `environments/freebsd/vm.py`'s `qemu_argv` gives arm64 `-machine virt -cpu max` and no `-accel kvm`, so on the maintainer's arm64 host the lane's own boot is emulated; the fast route, `--prepared` with `--runner-ssh` into a KVM guest started by hand, is documented only as "the supplied VM transport", and its flags had to be read from the source. `--runner-ssh` then wraps every guest command in `sudo -n /bin/sh -c` even when its login is root, so a development guest from the release image, which has no sudo, needs `pkg install sudo` first. Met running the FreeBSD arm64 runtime lane in a guest under KVM on that host on 2026-11-24.

Completion: on an arm64 host with an accessible `/dev/kvm` the lane boots its guest under KVM with the host's processor, `--runner-ssh` runs a root login's commands without sudo, and the lane's README gives the route to an existing guest.

Kept: aged past ten by R22.11, which changed `core/complex` and the math oracle and none of the FreeBSD lane or its guest transport; its activation, R21.61, has not run.

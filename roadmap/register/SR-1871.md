R22.24 made `timing.py run` refuse to time the RP2350's Arm port, `rp2350`, until its boot check has put the cores on Arm, naming the `run.py --board=rp2350 --mode=boot` step and the `rp2350_hazard3` boot check that restores the resting image. The run does not do either itself, because a timing bundle carries neither the port's fixed boot image nor the probehive runtime the boot check needs; so `timing.py remote` with no `--board`, which times every port in turn, refuses `rp2350` on a board at rest, and timing both Pico 2 ports by hand still takes two boot checks run around it.

Completion: `timing.py run` for `rp2350` switches the cores to Arm and back to the resting image itself, or `remote` runs the boot checks around it.
